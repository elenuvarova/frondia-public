# Скрипты

Индекс собран из докстрингов (`python3 scripts/index_scripts.py`). Живые скрипты работают через `engine/` и параметризованы по городу; прототипы — Брюссель-only, оставлены как история метода и для регрессий.


## Прогоны Earth Engine

- `gee/audit_beliris_landsat.py` — Аудит старых проектов Beliris прибором Landsat — с окнами под проект и порогом под окно
- `gee/audit_parks_city.py` — Пакетный аудит парков любого города из config.CITIES
- `gee/audit_parks_dated.py` — Аудит парков с ИЗВЕСТНОЙ датой сдачи — окно под проект, порог под окно, второй прибор
- `gee/baseline_preregistered.py` — Базовое состояние предрегистрированных следов — снимается СЕЙЧАС, до работ
- `gee/calibrate_city.py` — Калибровка прибора для любого города из config.CITIES
- `gee/calibrate_landsat.py` — Калибровка прибора Landsat: своё нулевое распределение и свой порог
- `gee/controls_preregistered.py` — Контроль для предрегистрированных следов — назван СЕЙЧАС, до работ
- `gee/effect_over_time.py` — Устойчивость эффекта во времени: посезонная разность разностей
- `gee/export_before_after.py` — Экспорт картинок «до / после» для сектора — визуальная проверка измеренного
- `gee/heat_exposure.py` — Тепловая нагрузка секторов: состояние, а не изменение
- `gee/monitor_season.py` — Мониторинг вперёд: что изменилось в городе за один сезон
- `gee/rule_3_30_300.py` — Правило 3-30-300 по секторам: признанная норма, посчитанная на наших данных
- `gee/third_canopy_reference.py` — Третий прибор на крону: Copernicus Global Land (Proba-V), 100 м — независимо от ESA и Google
- `gee/worldcover_reference.py` — Официальная крона: ESA WorldCover 10 м как независимая сверка нашего измерения

<details><summary>прототипы (до движка, только Брюссель)</summary>

- `gee/audit_one_park.py` — Аудит одного парка с настраиваемыми окнами — проверка чувствительности к срокам
- `gee/audit_parks_batch.py` — Пакетный аудит всех пригодных парков Брюсселя
- `gee/calibrate_dynamic_world.py` — Калибровка Dynamic World: нулевые распределения и пороги значимости

- `gee/dynamic_world_check.py` — Проверка Dynamic World как второго прибора рядом с NDVI
- `gee/equity_of_greening.py` — Кому досталось озеленение: анализ справедливости изменений 2017–2024
- `gee/placebo_band.py` — Полоса шума метода: плацебо на случайных секторах
- `gee/retro_audit.py` — Ретро-аудит городского вмешательства по спутниковым снимкам
- `gee/retro_audit_matched.py` — Ретро-аудит с ПОДОБРАННЫМ контролем вместо кольца

## Официальные слои ЕС: расчёт по методике Комиссии

- `official/art8_official.py` — Статья 8 по методике Комиссии: зелень и крона на официальных слоях Copernicus, исключение 45/10 по коммунам

## Реестры: сбор и связи

- `registry/antwerp_sector_names.py` — Названия антверпенских секторов и районы — из реестра Statbel, по коду сектора
- `registry/beliris_all_measured.py` — Все завершённые проекты Beliris против измеренных изменений — без фильтра по домену
- `registry/beliris_budgets.py` — Бюджеты проектов Beliris и цена измеренного эффекта
- `registry/beliris_dates.py` — Даты окончания и бюджеты ВСЕХ завершённых проектов Beliris — и что из них пригодно
- `registry/beliris_status_watch.py` — Сверка статусов Beliris: что сдвинулось с прошлого снимка
- `registry/commune_crosscheck.py` — Сверка реестра контрактов с измеренным изменением — на уровне коммуны
- `registry/contract_budgets_links.py` — Бюджеты квартальных контрактов и их привязка к измеренным паркам
- `registry/extract_greening.py` — Извлечение ПЛАНИРУЕМЫХ мер по озеленению из описаний квартальных контрактов
- `registry/fetch_agvespa.py` — Реестр проектов AG Vespa (Антверпен): статус, тема, хронология, год сдачи
- `registry/fetch_beliris.py` — Сбор реестра проектов Beliris и сверка с измеренными изменениями по паркам
- `registry/fetch_contracts.py` — Сбор реестра брюссельских квартальных контрактов с quartiers.brussels
- `registry/fetch_park_perimeters.py` — Сбор пригодных для аудита периметров парков Брюсселя из OpenStreetMap
- `registry/fetch_statbel_age.py` — Возрастная структура секторов: Census 2021, Statbel
- `registry/name_points.py` — Назвать точки линии выполнения: где урны нужнее всего — и случайный контроль
- `registry/name_points_planner.py` — Назвать точки линии выполнения из кандидатов City Planner: отсечка как контроль
- `registry/osm_appearance.py` — Прибор линии выполнения: был ли объект в названной точке на заданную дату
- `registry/preregister_beliris.py` — Первые настоящие записи предрегистрации — из проектов Beliris в статусе «в проекте»
- `registry/statbel_income.py` — Облагаемый доход по секторам из таблицы Statbel — медиана и среднее последнего года, для любого города

## Генераторы страниц и дел

- `report/article8_data.py` — Данные для отчёта по статье 8 регламента (EU) 2024/1991 — один город
- `report/article8_html.py` — Отчёт по статье 8 регламента (EU) 2024/1991 — HTML из данных города
- `report/atlas_data.py` — Данные для атласа: секторы города → упрощённые SVG-пути + атрибуты слоя ст. 8,
- `report/atlas_html.py` — Публичный атлас изменений — хороплет по секторам города, экран 3 в публичной форме
- `report/audit_case.py` — Сборка дела аудита: всё числовое — движком, всё человеческое — не трогаем
- `report/audit_case_dated.py` — Сборка дела аудита для проекта с известной датой сдачи — окно под проект, Landsat
- `report/audit_html.py` — Публичная страница аудита одного вмешательства — экран 2 из вайрфреймов
- `report/background.py` — Фон города: насколько город зеленел сам по себе и сколько секторов «значимы» без контроля
- `report/bundle.py` — Городской пакет: измеренные слои в `cities/<city>/layers/` с записью в манифесте
- `report/dossier_html.py` — Досье под заявку на финансирование: обоснование по одному сектору
- `report/import_projects.py` — Импорт слоёв и точек из соседних проектов Елены в городской пакет
- `report/landing_html.py` — Лендинг Frondia — экран 1. Герой — живой атлас города, не иллюстрация
- `report/method_html.py` — Страница метода: почему числу можно верить и где движок отказывается считать
- `report/monitoring_html.py` — Страница мониторинга: бюллетень сезона для одного города
- `report/paths.py` — Куда генераторы страниц пишут и откуда читают промежуточное
- `report/points_html.py` — Страница линии выполнения: точки, названные до проверки
- `report/registry_antwerp_html.py` — Страница реестра Антверпена: сколько вмешательств вообще поддаётся проверке
- `report/registry_html.py` — Реестр вмешательств — экран 6 в публичной форме
